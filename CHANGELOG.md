# Changelog

All notable changes to this project are documented here.

## [Unreleased]

- **New passwords of signing keys need at least 12 characters (`eh3d-project`, was 8):** it applies to a new key and to protecting a key file; `MIN_PASSWORD_CHARS` is 12, so the programs that show it, and the message in eight languages, say 12. A key file already under a password of 8 to 11 characters opens as before.
- **Third-party notices made from the dependency tree and checked in CI (`tools/third_party_notices.py`, `docs/THIRD_PARTY_NOTICES.md`):** `crates/project/THIRD_PARTY_NOTICES` is now complete, with the copyright lines of every crate (argon2 and chacha20poly1305 had none), the Apache-2.0 text that rpassword and rtoolbox ask for and the licences of the crates that were not listed. A new CI job fails when a dependency or a licence is missing from the file. Programs of the suite can use the same tool.

- **A drill file that does not declare its format can be refused until one is chosen (`eh3d-bungard-formats`, `docs/FORMAT_ERRORS.md`):** new `ncd::parse_as` and `parse_as_limited` take the format the person chose (`ncd::NumberFormat`: `mils`, `inch-2.4-tz`, `inch-2.4-lz`, `metric-3.3-tz`, `metric-3.3-lz` or other digits) and refuse with `EH3D-FORMATS-014` a file whose scale would have to be supposed; what a file declares wins over the choice. `ncd::how_to_choose` explains it in the eight languages and `ncd::MILS_DECLARATION` is the header by which a program of the suite declares the whole mils it writes. `ncd::parse` still reads as before, for showing a file; a `FILE_FORMAT` comment written with a blank is now taken, and a coordinate of zero no longer counts as a supposition. 4 tests.

- **Touch screens, the second question before the spindle or the laser goes on:** the shared code reads `pause.power_on` of a job and has the words for it in the eight languages (`firmware_base`). Host-tested only.

## [0.3.9] - Plots keep their relative mode, the GRBL controller sets the active work zero and an optional spindle stop on pause

- **Zeroing writes the work system in use (`eh3d-controller`, fix):** the GRBL controller always wrote `G54` (`G10 L20 P1`), also while the program worked in `G55` to `G59`; it now writes the system in use (`P0`). The simulated GRBL keeps the six work systems.
- **A pause can stop the spindle too (`eh3d-controller`, safety, off by default):** the feed hold leaves the spindle turning. `with_spindle_stop_on_pause(true)` adds the safety door byte of the firmware, which turns the spindle and the coolant off and turns them on again, with its delay, on a resume; a pause that the firmware does not confirm is an error. A line that waits while the machine is in the door state is no longer given up as unanswered, and a stop in that state resets without waiting three seconds.
- **A Marlin jog keeps to mm after `G20` (`eh3d-controller`, fix):** with inches left on by the program the jog went 25.4 times as far; it is now made in mm and the inches come back after it.
- **Other faults of the GRBL controller (`eh3d-controller`, fix):** a controller set to report in inches (`$13=1`) is read in mm once the setting has been seen; the late `ok` of a line that timed out is no longer taken for the answer to the next one; a restart seen while the settings are read is told. 12 tests of these changes, on the simulated machines; no real controller has answered them.
- **The two touch screens answer the question they show (`firmware_base`, safety):** the client of the server and the flow of the job send back the identifier of what the job asked (`pause.question`) with Continue and "Tool changed", and the table of refusals has `question_changed` and `question_required`. Checked by the host tests of the screens.

- **The relative mode of a plot lasts until an absolute one (`eh3d-bungard-formats`, fix):** only the coordinates written with `PR` itself were read as relative, so the `PU` and `PD` after it went to other places and the routing path was wrong. `PR` and `PA` now set the mode of the following commands, and `IN` and `DF` put it back to absolute; `DF` also ends the scaling.
- **What a plot asks for and the reader does not do is told (`eh3d-bungard-formats`, `docs/FORMAT_ERRORS.md`):** `hpgl::diagnose` and `parse_strict` give `EH3D-FORMATS-012` for a command that changes what is cut and is not followed (a rotation, a window, a rectangle, a label...) and `EH3D-FORMATS-013` for a scaling that is not applied as written (`SC` or `IP` without their arguments, user units with no `IP`). Programs that already refuse a plot with a finding now refuse these too.
- **A supposed coordinate format of a drill file is told (`eh3d-bungard-formats`):** an `INCH` header with nothing else is still read as whole mils, as before, while other programs read it as 2.4 inches, ten times less. `ncd::diagnose` now gives `EH3D-FORMATS-014` for it and for any other format that has to be supposed, and `ncd::parse_declared` refuses such a file; `ncd::parse` reads as before. 8 tests of these three changes.
- **The shared part of the two touch screens follows the screens (`firmware_base/`):** the warning shown before a job that goes on after a stop is let go, the reason of a resume the server does not do, their texts in the eight languages, the fonts built again with the new characters and their tests, as the two screens have them. Not seen on the module.

## [0.3.8] - Panels come to the front and fit narrow columns, results are not kept over newer saves and signing keys are safer at their edges

- **Signing keys at their edges (`eh3d-project`, `eh3d_dock::key_store`):** putting a password on a key through a link now protects the file the link points at, instead of replacing the link and leaving the key without a password behind it; a byte order mark before a password given on the standard input is no longer part of it; and a path too long to be read back is refused instead of being kept. 3 tests.
- **Asking for a panel brings it to the front (`eh3d-dock`, `docs/DOCKING.md`):** `DockAction::ShowPanel` did nothing seen for a panel that was already a tab behind another one. It now puts its tab on show, raises its floating window over the others and ends the maximising of another group; `Layout::bring_to_front` does the same for a program. Showing a panel from the View menu does too. 6 tests, 2 of them of the drawing.
- **The settings panel of the server keeps to the width of its column (`eh3d-view`, `docs/SERVER_CLIENT.md`):** in a narrow column the check that looks for the server was cut at the edge. Labels go over their boxes where the two do not fit side by side, long words wrap, buttons go to further rows and the list of sessions takes rows of its own. 4 tests of the drawing in the eight languages at several widths, now run in the CI.
- **A result is not kept over what another program saved since the project was opened (`eh3d-project`, `docs/FORMAT_EH3D.md`):** new `manufacturing::save_result_since` and `keep_result_since` take the mark of the opening and refuse with `EH3D-PKG-025`, writing nothing; `save_result` and `keep_result` stay as they were. `appbranch::open_unchanged` also judges what it opened, so a save made between its two readings is refused. 2 tests.
- **The shared part of the two touch screens draws every text of the eight languages (`firmware_base/`):** the fonts hold every character of every text, so Japanese and Chinese no longer fall back to English, and the refusal codes added by the server have their texts. Not seen on the module.

## [0.3.7] - Projects saved by another program are not written over, signing keys under a password and agreed signature replacement

- **Saving a `.eh3d` project is refused when another program saved it meanwhile (`eh3d-project`, `eh3d-attachpanel`, `docs/FORMAT_EH3D.md`, `docs/adr/0004-eh3d-safe-writes-and-keys.md`):** nothing is written over a file whose content is no longer the one that was read (new code `EH3D-PKG-025`), and the message says to open it again or to save under another name. The content counts, not the date, and the writes a program makes one after another do not count as another program. Every write of the crate checks it again just before the replacement (`write_atomic_checked` in the container). A window gets it from `suiteview::view` and `warnings`, which now refuse; `suiteview::check_unchanged`, `appbranch::open_unchanged` and `BranchKit::update_since` are there for the rest, and the panel of attachments refuses too and reads the list again.
- **Signature keys under a password (`eh3d-project`):** a new key file kept with **Argon2id** (64 MiB, 3 passes) and **XChaCha20-Poly1305**, in a versioned format of its own. The files without a password, made before, are read as before; `key_protection` tells which is which and `protect_key_file` puts one under a password. `eh3d-project keygen` asks for a password by default (`--password-stdin`, `--no-password`), `protect-key` is new, and `sign` warns about a key without one. Passwords and keys are never printed and are wiped from memory. New crates: `argon2` 0.6.0, `chacha20poly1305` 0.11.0, `rpassword` 7.5.5.
- **A signature is replaced only when agreed (`eh3d-project`):** `sign_branch` and `sign_project` refuse to put another signature over one that is there (`EH3D-PKG-026`); `signature_to_replace` lets a program ask first, `sign_branch_replacing` and `sign_project_replacing` do it, and the command line needs `--replace-signature`.
- **The path of the signing key is remembered (`eh3d_dock::key_store`):** one file for each program in the settings folder of the user, holding the path only, never the key or its password.
- **The text a preview keeps is a setting (`eh3d-viewer`):** `viewer.max_preview_mb`, 16 by default as before (`ViewerLimits::max_preview_bytes`).

- **Escape closes what the panel «Attachments» has open (`eh3d-attachpanel`):** the window that chooses files, then the question before a write, answered with no, then the form of a link, one at each press and with nothing written; with nothing open the key is left to the program.
- **Documents and projects made to cause harm no longer use up the memory or the time of a program (`eh3d-viewer`, `docs/VIEWER.md`):** a small workbook or sheet that showed one long value in many cells made the preview keep gigabytes; a preview now keeps at most 16 MB of text and gives back what it cuts. A Markdown file of open brackets took a time that grew with its square; the end of a link is now looked for within 4,096 bytes. 5 more tests, and 1 with the PDF library on damaged files.
- **What a file is, judged more carefully (`eh3d-filekind`):** a `.phoenixproj` is no longer marked as a compressed archive; a second end record in the comment of an office document can no longer hide its macros, and an archive that does not agree with its own list, or lists nothing, counts as one with macros, as do Excel macro sheets; a very long name can no longer be cleaned into one that ends in a dot or is a device name, which made a project report its own attachment as unsafe. 3 more tests.
- **Damaged or tampered projects and writes that fail (`eh3d-container`, `eh3d-project`, `docs/FORMAT_EH3D.md`):** a project opened without the integrity check refuses sizes in `integrity.json` that are not those of the archive (they could stop the program or pass the limits); a ZIP64 end record outside the file is an error instead of an overflow; the writer counts `integrity.json` against the total as the reader does, so it never writes a file it would refuse; `extract_branch` leaves no half file; an imported file called `report.json` is no longer written over by the report; on Linux and macOS a saved file keeps its permissions. 11 more tests.
- **Data of printers (`eh3d-printers`):** 2 more tests, of data files cut or changed and of the processes of every printer.

## [0.3.6] - Saving a project no longer compresses what did not change, tabs in rows and a readable About window

- **The window about a program reads on light themes (`eh3d-dock`):** the labels of the rows (version, author, e-mail and the others) and the heading of the notices came out white on a light ground in a program that paints a light theme over the dark visuals of egui, because strong text takes the colour of an active widget. `about_contents` and the plain list now work out their text, weak text and link colours from the ground of the window, each at 4.5:1 or more; a test reads every word drawn in every theme of the six programs. 1 more test.
- **Saving a project no longer compresses again what did not change (`eh3d-container`, `eh3d-project`, `docs/FORMAT_EH3D.md`):** the entries that stay, of other branches, attachments and files of the saved branch with the same content, are copied with their compressed bytes and CRC; the file keeps its one form (an entry stored another way by another tool is compressed again once) and projects written before open and save as before. The new file is now checked entry by entry (CRC and SHA-256) **before** it replaces the old one, instead of after, so a damaged entry, or one that is not what `integrity.json` says, refuses the save and leaves the file as it was. New in the container: `ContainerWriter::keep` and `write_to_path_from`. 9 more tests.
- **Tabs that do not fit go to further rows with their whole name (`eh3d-dock`, `docs/DOCKING.md`):** the tab bar grows by rows instead of cutting a title or writing the sign of the panel, the content starts under the last row, and tabs are dragged and dropped in any row. A title wider than a whole row is cut and shown whole under the pointer; a bar takes at most half the height of its group (never fewer than two rows). 7 more tests, with long German, Chinese and Japanese titles, very narrow panels, the height of the content and dragging in every row.

## [0.3.4] - Attachments panel and viewer, one file classification and short tab titles written in full

- **The panel «Attachments» takes its limits from the settings and takes dropped files (`eh3d-attachpanel`, `docs/ATTACHMENTS_PANEL.md`):** `PanelLimits` reads `attachments.max_mb` and `viewer.max_*_mb` from the lines of a settings file and `AttachPanel::set_limits` puts them in force. `AttachPanel::take_drop` attaches a file dropped on the panel and leaves the program its own files; where the system does not say where the pointer is, the panel asks first. The SHA-256 of a file chosen for a link is taken on a thread of its own, so a large file no longer stops the window.
- **A tab with a short title writes it (`eh3d_dock::gui`):** a title of a few characters, as most are in Chinese and Japanese, was replaced by the sign of its panel («L» for Layers) although it fitted whole. The sign is now shown only when the tab is narrow and would cut the title; long titles are clipped as before. 3 tests, 2 of them of the drawing.
- **The panel «Attachments» that every PHOENIX program mounts, new crate `eh3d-attachpanel` (`docs/ATTACHMENTS_PANEL.md`):** the list of the attachments of the project, attach a file or a link, link to a component and filter by it, extract and remove with a confirmation, the viewer beside the list and its own window to choose files, folders and, for a program with no project menu, the project. A write that removes a signature is asked about, a settings file that holds `server_token` is not put into a project, the work runs on a thread of its own and the project is read again when another program wrote it. Eight languages; the model is tested without a screen.
- **One classification of files, new crate `eh3d-filekind`, and one careful rule:** the container and the viewer had two copies of it. Programs, scripts, documents with macros, compressed archives, HTML, SVG **and kinds the suite does not know** now ask for confirmation before they are extracted or opened. `AttachError::NeedsConfirmation` carries an optional danger (none for an unknown kind), `eh3d_project::attachfile` is gone (`AttachmentKind` and `Danger` stay re-exported), the viewer takes the danger that the record of a project says (`Source::declared_danger`), a zip is no longer expected behind `.csv` or `.tsv`, and `.eh3d`, `.eh3dproj`, `.phoenixproj` and `.lbrn2` are kinds the suite knows.
- **Attachments in the `.eh3d` project (`eh3d_project::attachments` and `attachfile`, `docs/FORMAT_EH3D.md`, `docs/adr/0003-eh3d-attachments.md`):** any file (data sheets, manuals, office documents, projects and drawings, video, sound or anything else) goes in the shared branch `attachments/`, stored once under the SHA-256 of its content and linked to the pieces of the design that use it (designator, value, or part number with or without manufacturer), or kept only as a link with its address and hash. Programs, scripts, documents with macros, compressed archives and pages that can run code are marked dangerous and taken out only when a person agrees; nothing is run or downloaded, names are cleaned and never become paths. One attachment may be up to 1 GiB (`attachments.max_mb`) and the project stays under 4 GiB; files are read and written in blocks and large ones are stored in parts, so older readers keep opening the project. New commands `eh3d-project attach`, `attach-link`, `attachments`, `extract-attachment`, `attachment-links` and `detach`; `AttachmentSource` reads one attachment for a viewer, and the warnings are in `suitetext` in the eight languages. The windows of the programs do not show attachments yet.
- **The viewer of the attachments of a project, new crate `eh3d-viewer` (`docs/VIEWER.md`):** what a file is and whether it is dangerous (programs, scripts, macros found inside, compressed archives, pages that run code, unknown kinds, and executables hiding behind a harmless name); a panel with no window in it and its drawing with egui (feature `gui`); PDF pages with zoom, fit width and search, drawn on a thread of their own by PDFium 160.0.8165.0 without a script engine or XFA, pinned by version and SHA-256 and loaded only from the folder of the program (`tools/fetch_pdfium.py` puts it there, licences included, and `crates/viewer/THIRD_PARTY_NOTICES` names them); the text and tables of docx, xlsx, pptx, odt, ods, odp and rtf within limits against archives that unpack to far more than their size, with no document type declarations and no external links; pictures, text, Markdown and tables of values inside; opening outside through a private temporary copy under a cleaned name, with confirmation for dangerous and unknown files and never launching a program or a script. Attachments up to 1 GB, changeable in the settings. The words are in the eight languages. Synthetic files in the tests; the real library is tried in the CI on Linux, Windows (64 and 32 bits) and macOS. No program uses it yet.

New commands `eh3d-project keygen` and `sign`, and `verify` has `--pubkey` and `--require-project-signature` and prints the state of every signature. The tests check the vectors of RFC 8032, a changed byte with and without a rewritten record, damaged signature records, random damage to whole files and damaged key files, with fixed seeds. The licences of the new crates are in `crates/project/THIRD_PARTY_NOTICES`.
- **What a program does with its own branch, written once (`eh3d_project::appbranch`):** `BranchKit` saves, opens, imports a file of another program with the original and the report of the conversion, takes a file of another branch with the reference to the state of its source and says what is out of date; `list`, `extract`, the bounded read and the identifier of a new project are there too, with typed notes (`Notice`) and errors (`BranchError`). No program has been changed: each adopts it in its own round and keeps the keys of the record of its branch.
- **The error catalog of the client has the whole catalog of the server again:** `authorization_required` and `stale_authorization`, and the seven codes of the pick-and-place nodes, with their texts in the eight languages; the texts of the binary G-code and Bambu LAN refusals follow the ones of the Studio.
- **The window «About» of the PHOENIX programs (`eh3d_dock::about`, `Dock::set_brand`, `gui::about_contents`):** the picture of the program inside a ring of its accent colour (fire orange, green, blue, steel cyan, red and violet), the name in large letters, one sentence about the program in the eight languages, the version, the author, the e-mail, the page of the author, the repository and the licence with links that can be clicked, the notices of data of others where a program carries them and the notice about trademarks. A program gives only which one it is and the bytes of its picture; `AboutInfo` and `Dock::set_about` are unchanged, and a program that gives no brand keeps the plain window. The feature `gui` of `eh3d-dock` now uses `png` 0.17 to read the picture. Six tests more, two of them of the drawing.
- **A catalog of 3D printers (`eh3d-printers`, `docs/PRINTERS.md`):** one record per model with the build volume, the nozzles, the enclosure, the highest temperatures, the multicolour system, the firmware, the family of adapter that would talk to it and the files it takes, for the Bambu Lab A1 and P1S, the Creality K1C and Ender-3 V3 KE and the Artillery Sidewinder X4 Plus S1 and X4 Pro S1. Every claim names the public page of the maker that says it, what is not published is left as unknown, an adapter the maker does not document says so, and nothing is marked verified. The schema is versioned and strict (unknown fields, figures out of range or not numbers, texts that would break a settings file and claims without a source are refused, with the codes `EH3D-PRN-001` to `EH3D-PRN-009`).
- **Where to start from on a printer:** the generic filaments of `eh3d-printmaterials` seen against a machine and a nozzle, with the reasons against the ones it cannot print and the cautions, and draft, standard, fine and strong processes computed from the nozzle from ratios written for the suite. Every word shown is in the eight languages. 22 tests, the hostile cases included.

## [0.3.1] - Shared project container with one branch per program, and the eight languages of the project

- **The `.eh3d` project container, one file with a branch for each program (`eh3d-project`, `docs/FORMAT_EH3D.md`, `docs/adr/0002-eh3d-project-container.md`):** the new crate opens, checks and saves the branches of a project (`pcb/`, `cad/`, `3dp/`, `laser/`, `cnc/`, `common/`, `manufacturing/`, `docs/<program>/` and `x-*/`) on top of `eh3d-container`. Each program writes only its own branch (`EH3D-PKG-017` otherwise), saving a branch leaves the bytes of every other entry as they were, and a branch that is not known is kept byte for byte. Every branch has a `branch.json` with the program, the format of the branch, the version of the program, the content hash of its files and its references to other branches with the hash and the version they were taken at; a branch derived from another whose source has changed is reported as out of date (a warning, `EH3D-PKG-019`), and `Project::dependency_on` writes the fresh reference. The `manufacturing` branch holds a `.eh3dproj` 1.0.0 package and gives it back byte for byte (the three reference packages do the round trip in the tests); the `.eh3dproj` code and its reference corpus are unchanged. Optional and checked when present: the metadata of the project (`common/meta/meta.json`, texts in the eight languages, English required), the documentation of each program with an index of documents and translations, and the original file of an import with the report of what was read and what was not. Security is optional and off by default: the seal read-only of a branch or of the project, the audit log, the records and checks of signatures (the keys are never in the file; the program gives the `Signer` and the `Verifier`) and the record of an encrypted branch, which is refused for reading and kept as it is. The cipher and a signature algorithm are not written yet (no crate for them is in the offline cache of the build; the ADR says what was chosen and why).
- **Ten new codes, `EH3D-PKG-015` to `EH3D-PKG-024`:** a record missing or invalid, a branch hash that differs, a write to a branch of another program, a reference between branches that is invalid or dangling, derived data out of date (the only warning, `PkgCode::is_warning`), a sealed branch or project, a signature that does not verify, a signature required and missing, a branch encrypted without its key and a branch format newer than supported. Codes 001 to 014 keep their numbers and titles (a test checks it) and the registry of the documentation repository lists the ten.
- **`eh3d-project info|verify|extract-branch` and a made-up sample file:** `info` lists the branches (`--json` too), `verify` prints the findings with their codes and ends with `VERIFY=PASS` or `VERIFY=FAIL` (`--strict`, `--require-signed`), `extract-branch` takes a branch out of the file, or the `manufacturing` branch as a `.eh3dproj`, and never replaces a file. `crates/project/tests/data/synthetic.eh3d` is a project with invented data that the tests rebuild and compare byte for byte.
- **43 tests for the project container, with fixed seeds:** the synthetic project is sound; saving a branch keeps the bytes of every other entry (24 saves of random content to random branches) and saving the same content again gives the same file; damaged files (120 files with a flipped bit, a cut, overwritten bytes or bytes added) are refused or reported and never stop the reader; the limits of entries and of the size of an entry apply; the golden packages come out of `manufacturing` byte for byte; the ownership, the seal, the references, the signatures with a test double, the encrypted branch, the optional records and the command line.

## [0.0.1] - The project container, its metadata and the machine telemetry types

- **The `.eh3dproj` container:** a ZIP archive with `project.json`, `integrity.json` and the folders `layers/`, `toolpaths/` and `vision/`. The writer is deterministic and writes through a temporary file.
- **Integrity:** the SHA-256 and the size of every entry are recorded; a package with a changed, missing or unlisted entry does not open.
- **Limits:** entry names that could leave the package folder are refused, and so are oversized or too many entries.
- **Metadata:** name, identity, units, zero of the workpiece, layers, tools, toolpaths and fiducials, validated, with a semantic format version: a newer major version is refused and an older one needs a registered migration (there is none yet).
- **Telemetry types:** axes, spindle, machine states and GRBL alarm codes with their severity.
- **Theme:** the colours of the suite with a contrast check.
- **Firmware base of the nodes:** `firmware_base/`, the part of the ESP32 node firmware that every EH3D node shares (settings, network, panel server, users and sessions, update with rollback, log, self-protection, tests), written once with the project's name as placeholders, and `tools/sync_firmware_base.py` to write it into the nodes and check the copies. CI runs the check.
- 29 tests, `cargo clippy -D warnings` and `cargo fmt --check` in CI on Linux and Windows, and a repository check of the manifest, the versions, the changelog and the eight README files.
